# 家電の解決ノート専用GA4（2026-11-01）

## 実装

運営者指定の測定ID `G-VSQ7Q0E6HF` を `config/analytics.json` に保存します。KURACALのファイル・GA4設定は一切変更していません。他リポジトリや共通環境変数から測定IDを継承せず、この設定だけを使用します。

既存の本番判定（Cloudflare Workers Builds main・承認済み・実際のWrangler deploy）でのみ、共通headにGoogleタグの非同期ローダー1回と初期化/config命令1回を生成します。404を含む配信対象の全36 HTMLが対象です。404のnoindexは維持します。標準configの自動page_viewを使用し、別の手動page_viewやGTMコンテナは追加しません。

preview/dev/他ブランチにはGoogleタグや初期化命令を生成しません。Cloudflareの環境変数追加は不要です。AdSenseの生成条件・publisher・ads.txtは変更しません。

プライバシーポリシーのGA4未導入という記述を更新し、利用目的・Cookie等・Googleの説明・オプトアウト方法を案内します。23記事の本文・タイトル・description・URL・更新日、CSS/JS、冬の導線、関連記事、canonical/sitemap/robots/noindex設定は変更しません。HTTP→HTTPSは今回の対象外です。

## 検証方法

- build_check.py：本番全36 HTMLのhead内ローダー1回・config1回、preview/dev/他ブランチ0回、環境変数の別IDを無視、無効IDのビルド拒否。既存AdSense・リンク・SEOも回帰検査。
- production_package_check.py：一時コピーでmainのプロセス観測を模擬してWrangler dry-run。本番へはデプロイしません。
- ga4_candidate_check.py：一時コピーの本番HTMLをブラウザ内で正式URLへ割り当て、Googleの実gtag.jsを読み込みます。収集通信はテスト内で204応答に置き換えて、Analyticsには送信しません。トップと記事でpage_viewが各1回、送信先ID・ページURL・タイトルを照合。通信abortは再送を起こす場合があるため、204で検査します。
- ga4_preview_check.py：Cloudflare実プレビューの全36 HTMLでローダー・gtagグローバルなし、ブラウザのAnalytics通信0件を確認。
- site_check.py：35ルート×375/768/1440px、23記事・8カテゴリ・検索・冬導線・関連記事・モバイル・保存機能・404を確認。
- adsense_live_check.py、live_seo_check.py：プレビューで広告通信なし・noindex維持を確認。承認後の本番では従来のコード・ads.txt・SEOを再確認します。

## 確認の限界と承認後

**本番未反映のため、実本番のpage_view送信とGA4管理画面での受信は未確認です。** 本番候補でのイベント生成の成功と、Google側での受信を混同しません。事前テストでは本番プロパティへテストイベントを送りません。

公開承認後にmainへマージし、Cloudflare本番deploy成功を確認します。その後全36 HTMLのローダー/config、AdSense/ads.txt、表示・SEOを実URLで再検査。通常のページ閲覧で送信先がG-VSQ7Q0E6HF、event名がpage_view、ページURL/タイトルが正しいことを確認し、GA4のリアルタイムレポートで受信を確認します。管理画面にアクセスできない場合は、その受信確認を運営者へ依頼して未確認として報告します。
